# S1 Accounts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person can sign in to mychess by email magic link, Google or Lichess, finish a one-screen onboarding, change their name and language, link and unlink providers, export their data and delete their account. Each canonical email has exactly one account, and staging personas can sign in through a test-only route.

**Architecture:** Better Auth (ADR 0010) runs inside `apps/web`, behind a factory `createAuth({ db, env, mail })` so feature tests can build it against a Testcontainers database with a fake mailer and a fake OAuth `fetch`. Its tables live in `packages/db`'s Drizzle schema under our own names (`accounts`, `sessions`, `provider_accounts`, `verifications`), plus `admin_audit`. The rules (canonical email, onboarding, the delete check, entitlement limits) are pure functions in `packages/domain`. Everything else (deleting, exporting, granting and disabling) is a repository function in `packages/db`. Pages use the Better Auth React client for sign-in and linking, and server actions for profile, onboarding and delete.

**Tech Stack:** better-auth 1.7.10 (magic-link and generic-oauth plugins, Drizzle adapter), Next.js 16 App Router, next-intl 4, Drizzle 0.45 on Postgres 18, zod 4, vitest 4 (feature suite on Testcontainers), Playwright 1.64 with Mailpit.

**Spec:** `docs/superpowers/specs/2026-10-16-s1-accounts-design.md`. **Issue:** #251 (epic #250). **Rulings:** R-1, R-3, R-26, R-27, R-40, R-68 to R-70, R-72, R-73, R-80 to R-83; security checklist items 6-10 on #233. **Blocked on:** nothing. Staging verification waits for #234.

**Roles:** each task names its role. `- SECURITY` tasks go through `security-reviewer`; `- UX` tasks go through `ux-designer` and `i18n-content`. Only the lead commits.

**Rules for every task** (CLAUDE.md): test first; no suppression comments, no `any`, no `!`; functions small (complexity <= 10); every user-visible string goes through `apps/web/src/i18n/messages/{lt,en}.json`; refusals are `Result` values with catalogue keys; parse every request body, query result and external response with zod. After each task run `node quality/gate.mjs check` (needs Docker). Workers report the files they changed and the commands they ran; the lead commits. Where a test below uses `!` for brevity, use a small `must(value)` helper that throws on `undefined`, and keep the assertions the same.

**Better Auth names:** Task 1 checks the installed `.d.mts` files. If a name below differs in 1.7.10, use the installed name and report it. The names were read from the 1.7.10 package while planning: `magicLink` (`better-auth/plugins/magic-link`), `genericOAuth` (`better-auth/plugins/generic-oauth`), `drizzleAdapter` (`better-auth/adapters/drizzle`), `nextCookies` (`better-auth/next-js`), `createAuthMiddleware` and `APIError` (`better-auth/api`), `makeSignature` (`better-auth/crypto`), `account.accountLinking.{enabled, disableImplicitLinking, trustedProviders, allowDifferentEmails, allowUnlinkingAll}`, `account.encryptOAuthTokens`, `session.{expiresIn, updateAge}`, magic link `{ expiresIn, sendMagicLink({ email, url, token, metadata }), storeToken }`, generic OAuth config `{ providerId, clientId, authorizationUrl, tokenUrl, scopes, pkce, getUserInfo }`.

## Decisions taken while planning

These fill gaps the spec leaves to the lead. None of them is a product rule; R-83 was asked and ruled.

1. **Table names follow the domain language.** Better Auth's `user` is our `accounts` table and its `account` (a provider link) is `provider_accounts`. The mapping is `user.modelName` and `account.modelName`, and `user.fields.name` is mapped to `displayName`. CONTEXT.md says to avoid "User" in domain talk.
2. **Onboarding is recorded by `onboardedAt`**, not by "has a display name". R-81 prefills the name from Google or Lichess, so a non-blank name cannot mean the person has seen the onboarding screen. `isOnboarded(account)` is `account.onboardedAt !== null`.
3. **Mailpit is reached over its HTTP send API** (`POST /api/v1/send`), and Resend over its REST API (`POST https://api.resend.com/emails`). Both transports are a `fetch`, so there is no SMTP or Resend SDK dependency. `MAIL_TRANSPORT` is `resend | mailpit` (the spec said `smtp`).
4. **Session renewal:** `expiresIn` is 90 days and `updateAge` is 1 day. Any visit more than a day after the last renewal pushes expiry to 90 days from that visit (R-80).
5. **Admin audit (checklist item 8):** an append-only `admin_audit` table. `grantAdmin` and `disableAccount` each write exactly one row in the same transaction as the change. Two CLI scripts, `admin:grant` and `admin:disable`, are the only callers. There is no admin UI in S1.
6. **Unlinking:** `allowUnlinkingAll: true`. The magic link to the account's canonical email always works, so unlinking every provider never locks a person out.
7. **Lichess identity lives in `apps/web/src/server/oauth/lichess.ts` for S1.** `packages/integrations` is not scaffolded yet (#244). It moves there when integrations-dev scaffolds the package.
8. **Better Auth endpoints we do not use are disabled** (`disabledPaths`): `/update-user`, `/delete-user`, `/change-email`, `/sign-up/email`, `/sign-in/email`. Profile changes and deletion go through our own server actions so the domain rules apply. Account fields we add are `input: false`, so no client can set `admin`, `disabledAt`, `entitlement` or `onboardedAt`.
9. **OAuth tokens are encrypted at rest** (`encryptOAuthTokens: true`, checklist item 7). Google is not a trusted provider, so it joins an existing account only when Google's `email_verified` is true. Lichess is in `trustedProviders` (Better Auth 1.7.10 refuses a settings link from an untrusted, unverified provider). Trusting it would also let a sign-in link it implicitly by email, so a guard forbids that: `databaseHooks.account.create.before` lets a `lichess` provider link be created only (a) for an account created in this same request (a new Lichess sign-up, marked by `user.create.before` in a per-request `WeakSet`), or (b) when the request's session (`getSessionFromCtx`) belongs to that same account (linking from settings). Any other Lichess link (implicit linking at sign-in) is refused, and the sign-in page maps the resulting error code to the R-83 message.
11. **Better Auth 1.7.10 corrections (Task 1 findings):** generic OAuth providers use the social routes (`POST /sign-in/social`, `/callback/lichess`, `POST /link-social`, all with `provider: 'lichess'`). There is no `genericOAuthClient`: the client has `signIn.social`, `linkSocial`, `unlinkAccount({ accountId })` (the `provider_accounts.id` from `listAccounts()`), and `listAccounts`. A custom Google `getUserInfo` returns no `user.id`; Better Auth reads the id from `data.sub`. Implicit linking needs the existing account to have `emailVerified: true` (`requireLocalEmailVerified`), so test fixtures that expect Google to join must set it.
10. **Local infrastructure:** `infra/compose.yaml` runs Postgres 18.6 and Mailpit for `next dev` and local E2E. CI's `e2e` job gets the same two images as service containers.

```ts
import type { Result } from '@mychess/chess';
import { z } from 'zod';

/** The site's languages: Lithuanian first (R-1). */
export const LOCALES = ['lt', 'en'] as const;
export type Locale = (typeof LOCALES)[number];

/** Commercial levels; everything is free in the MVP (R-3, R-70). */
export const ENTITLEMENTS = ['free'] as const;
export type Entitlement = (typeof ENTITLEMENTS)[number];

/** Message-catalogue keys for account refusals; the UI translates them. */
export const ACCOUNT_REFUSALS = {
  emailInvalid: 'account.emailInvalid',
  deleteNameMismatch: 'account.deleteNameMismatch',
} as const;

export type AccountRefusal = {
  reason: (typeof ACCOUNT_REFUSALS)[keyof typeof ACCOUNT_REFUSALS];
};

/** One signed-in person, as the database hands it over (parsed at the edge). */
export const accountSchema = z.object({
  id: z.string().min(1),
  email: z.string().min(1),
  displayName: z.string(),
  locale: z.enum(LOCALES),
  entitlement: z.enum(ENTITLEMENTS),
  admin: z.boolean(),
  disabledAt: z.date().nullable(),
  onboardedAt: z.date().nullable(),
  createdAt: z.date(),
});
export type Account = z.infer<typeof accountSchema>;

const emailSchema = z.email();

/**
 * The one form of an email an Account is keyed by: NFKC, trimmed, lowercase.
 * Anything that is not a single plain address is refused, so look-alikes
 * never become a second account (security item 6).
 */
export function canonicalEmail(raw: string): Result<string, AccountRefusal> {
  const folded = raw.normalize('NFKC').trim().toLowerCase();
  return emailSchema.safeParse(folded).success
    ? { ok: true, value: folded }
    : { ok: false, refusal: { reason: ACCOUNT_REFUSALS.emailInvalid } };
}

/** Has the account been through the onboarding screen (R-81)? */
export function isOnboarded(account: Account): boolean {
  return account.onboardedAt !== null;
}

/** Deletion is confirmed by typing the display name exactly (R-82). */
export function canDelete(
  account: Account,
  typedName: string,
): Result<undefined, AccountRefusal> {
  return typedName.trim() === account.displayName
    ? { ok: true, value: undefined }
    : { ok: false, refusal: { reason: ACCOUNT_REFUSALS.deleteNameMismatch } };
}

export interface EntitlementLimits {
  readonly coachPlayers: number;
  readonly coachGroups: number;
}

const LIMITS: Record<Entitlement, EntitlementLimits> = {
  free: { coachPlayers: 30, coachGroups: 10 },
};

/** What an entitlement allows; S4 enforces the coach limits. */
export function entitlementLimits(entitlement: Entitlement): EntitlementLimits {
  return LIMITS[entitlement];
}
```

```ts
// The database schema: every table, as drizzle-kit reads it to generate
// migrations (drizzle.config.ts). Better Auth's four tables carry our names
// (src/server/auth.ts in apps/web maps them): its "user" is our Account and
// its "account" is a provider link.
import {
  boolean,
  index,
  pgTable,
  serial,
  text,
  timestamp,
  uniqueIndex,
} from 'drizzle-orm/pg-core';

const at = (name: string) => timestamp(name, { withTimezone: true });

export const accounts = pgTable('accounts', {
  id: text('id').primaryKey(),
  /** The canonical email (domain canonicalEmail); one account each. */
  email: text('email').notNull().unique(),
  emailVerified: boolean('email_verified').notNull().default(false),
  displayName: text('display_name').notNull(),
  image: text('image'),
  locale: text('locale', { enum: ['lt', 'en'] }).notNull().default('lt'),
  entitlement: text('entitlement', { enum: ['free'] }).notNull().default('free'),
  admin: boolean('admin').notNull().default(false),
  disabledAt: at('disabled_at'),
  onboardedAt: at('onboarded_at'),
  createdAt: at('created_at').notNull(),
  updatedAt: at('updated_at').notNull(),
});

export const sessions = pgTable(
  'sessions',
  {
    id: text('id').primaryKey(),
    token: text('token').notNull().unique(),
    accountId: text('account_id')
      .notNull()
      .references(() => accounts.id, { onDelete: 'cascade' }),
    expiresAt: at('expires_at').notNull(),
    ipAddress: text('ip_address'),
    userAgent: text('user_agent'),
    createdAt: at('created_at').notNull(),
    updatedAt: at('updated_at').notNull(),
  },
  (t) => [index('sessions_account_id_idx').on(t.accountId)],
);

export const providerAccounts = pgTable(
  'provider_accounts',
  {
    id: text('id').primaryKey(),
    /** The provider's id for the person (Google sub, Lichess username id). */
    providerAccountId: text('provider_account_id').notNull(),
    providerId: text('provider_id').notNull(),
    accountId: text('account_id')
      .notNull()
      .references(() => accounts.id, { onDelete: 'cascade' }),
    accessToken: text('access_token'),
    refreshToken: text('refresh_token'),
    idToken: text('id_token'),
    accessTokenExpiresAt: at('access_token_expires_at'),
    refreshTokenExpiresAt: at('refresh_token_expires_at'),
    scope: text('scope'),
    password: text('password'),
    createdAt: at('created_at').notNull(),
    updatedAt: at('updated_at').notNull(),
  },
  (t) => [
    uniqueIndex('provider_accounts_provider_idx').on(t.providerId, t.providerAccountId),
    index('provider_accounts_account_id_idx').on(t.accountId),
  ],
);

/** Magic-link tokens and OAuth state; short-lived, keyed by `identifier`. */
export const verifications = pgTable(
  'verifications',
  {
    id: text('id').primaryKey(),
    identifier: text('identifier').notNull(),
    value: text('value').notNull(),
    expiresAt: at('expires_at').notNull(),
    createdAt: at('created_at').notNull(),
    updatedAt: at('updated_at').notNull(),
  },

/**
 * Append-only record of every Admin action (security item 8). No foreign
```

```ts
/**
 * Hard delete (R-40, R-82): the account and, by cascade, its sessions and
 * provider links; its pending magic-link tokens are matched by email.
 * Later slices extend the cascade with the rows they add.
 */
export async function deleteAccount(db: Executor, id: string): Promise<void> {
  const account = await findAccountById(db, id);
  if (account === undefined) return;
  await db.transaction(async (tx) => {
    await tx.delete(verifications).where(
      sql`case when ${verifications.value} ~ '^\\s*\\{' then ${verifications.value}::jsonb ->> 'email' end = ${account.email}`,
    );
    await tx.delete(accounts).where(eq(accounts.id, id));
  });
}

  readonly account: {
    readonly email: string;
    readonly displayName: string;
    readonly locale: Locale;

    readonly createdAt: string;
  };

}

export async function exportAccount(db: Executor, id: string): Promise<AccountExport | undefined> {
  const account = await findAccountById(db, id);

    .select({ provider: providerAccounts.providerId, linkedAt: providerAccounts.createdAt })
    .from(providerAccounts)

      locale: account.locale,
      entitlement: account.entitlement,
      createdAt: account.createdAt.toISOString(),
    },
    linkedProviders: links.map((l) => ({ provider: l.provider, linkedAt: l.linkedAt.toISOString() })),
```

```ts
import type { Result } from '@mychess/chess';
import { eq } from 'drizzle-orm';
import type { Db } from './client';
import { accounts, adminAudit, sessions } from './schema';

export type AdminRefusal = { reason: 'admin.accountNotFound' };
type AdminAction = (typeof adminAudit.$inferInsert)['action'];

/**
 * Runs one Admin change and its audit row in a single transaction
 * (security item 8). `email` must be canonical.
 */
async function audited(
  db: Db,
  email: string,
  actor: string,
  now: Date,
  action: AdminAction,
  change: (tx: Parameters<Parameters<Db['transaction']>[0]>[0], id: string) => Promise<void>,
): Promise<Result<undefined, AdminRefusal>> {
  return db.transaction(async (tx) => {
    const [row] = await tx.select({ id: accounts.id }).from(accounts).where(eq(accounts.email, email)).limit(1);
    if (row === undefined) return { ok: false, refusal: { reason: 'admin.accountNotFound' } };
    await change(tx, row.id);
    await tx.insert(adminAudit).values({ action, targetAccountId: row.id, targetEmail: email, actor, at: now });
    return { ok: true, value: undefined };
  });
}

/** Makes an account an Admin (R-72); only the CLI calls this. */
export function grantAdmin(db: Db, email: string, actor: string, now: Date): Promise<Result<undefined, AdminRefusal>> {
  return audited(db, email, actor, now, 'grant-admin', async (tx, id) => {
    await tx.update(accounts).set({ admin: true, updatedAt: now }).where(eq(accounts.id, id));
  });
}

/** Disables an account and ends every session it has, at once (R-80). */
export function disableAccount(db: Db, email: string, actor: string, now: Date): Promise<Result<undefined, AdminRefusal>> {
  return audited(db, email, actor, now, 'disable-account', async (tx, id) => {
    await tx.update(accounts).set({ disabledAt: now, updatedAt: now }).where(eq(accounts.id, id));
    await tx.delete(sessions).where(eq(sessions.accountId, id));
  });
}
```

```ts
/**
 * Google's identity from the id token that Google's token endpoint just
 * returned over TLS (so it is read, not re-verified). Only a verified
 * email is accepted (spec: "Google: verified email only").
 */
export async function googleUserInfo(tokens: { idToken?: string | undefined }) {
  const payload = tokens.idToken?.split('.')[1];
  if (payload === undefined) return null;
  const claims = claimsSchema.safeParse(JSON.parse(Buffer.from(payload, 'base64url').toString('utf8')));
  if (!claims.success) return null;
  const c = claims.data;
  return {
    user: { email: c.email, name: c.name ?? '', image: c.picture, emailVerified: true },
    data: c,
  };
}
```

```ts
import { z } from 'zod';

const accountSchema = z.object({ id: z.string().min(1), username: z.string().min(1) });
const emailSchema = z.object({ email: z.string().min(1) });

/**
 * The Lichess identity behind an access token (scope `email:read`, R-83).
 * The email is reported unverified, so Better Auth never links it to an
 * existing account implicitly (R-69).
 */
export function lichessUserInfo(fetchImpl: typeof fetch = fetch) {
  return async (tokens: { accessToken?: string | undefined }) => {
    if (tokens.accessToken === undefined) return null;
    const init = { headers: { authorization: `Bearer ${tokens.accessToken}` } };
    const [account, email] = await Promise.all([
      fetchImpl('https://lichess.org/api/account', init).then((r) => r.json()),
      fetchImpl('https://lichess.org/api/account/email', init).then((r) => r.json()),
    ]);
    const a = accountSchema.safeParse(account);
    const e = emailSchema.safeParse(email);
    if (!a.success || !e.success) return null;
    return { id: a.data.id, name: a.data.username, email: e.data.email, emailVerified: false };
  };
}
```

```ts
import { timingSafeEqual } from 'node:crypto';
import { canonicalEmail } from '@mychess/domain';
import { z } from 'zod';
import type { WebEnv } from './env';

export interface TestSignInDeps {
  readonly env: Pick<WebEnv, 'MYCHESS_ENV' | 'MYCHESS_TEST_SIGNIN' | 'TEST_SIGNIN_SECRET'>;
  /** Finds or creates the account and starts a session; returns its Set-Cookie. */
  readonly signIn: (email: string) => Promise<string>;
}

const bodySchema = z.object({ email: z.string() });

const sameSecret = (given: string, expected: string) =>
  given.length === expected.length && timingSafeEqual(Buffer.from(given), Buffer.from(expected));

/**
 * Persona sign-in for staging (R-73): absent (404) unless the flag is set
 * outside production; only `@mychess.test` with the shared secret.
 */
export async function testSignIn(request: Request, { env, signIn }: TestSignInDeps): Promise<Response> {
  if (env.MYCHESS_ENV === 'production' || !env.MYCHESS_TEST_SIGNIN || env.TEST_SIGNIN_SECRET === undefined)
    return new Response(null, { status: 404 });
  const body = bodySchema.safeParse(await request.json().catch(() => null));
  const email = canonicalEmail(body.success ? body.data.email : '');
  const allowed = email.ok && email.value.endsWith('@mychess.test')
    && sameSecret(request.headers.get('x-test-secret') ?? '', env.TEST_SIGNIN_SECRET);
  if (!allowed || !email.ok) return new Response(null, { status: 403 });
```
